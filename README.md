# Сборка и запуск
Для сборки необходим cmake и компилятор для c++ с поддержкой c++23
```
mkdir build && cd build
cmake .. 
cmake --build .
```

Для тестирования работоспособности необходим образ ФС. Тестировалось на linux alpine
```
mkdir -p /tmp/alpine
cd /tmp/alpine
wget https://dl-cdn.alpinelinux.org/alpine/v3.19/releases/x86_64/alpine-minirootfs-3.19.0-x86_64.tar.gz
tar -xzf alpine-minirootfs-3.19.0-x86_64.tar.gz
rm alpine-minirootfs-3.19.0-x86_64.tar.gz
```

Пример запуска контейнера
```
./runtime --rootfs /tmp/alpine /bin/sh
```

# Реализация
Создание дочернего процесса из лабораторной 3.

Master и Slave концы терминала открываются в конструкторе PtyChannel. 
С помощью `posix_openpt` получаю master handle, делаю его не управляющим (O_NOCTTY). Выдаю права, разблакирую slave конец (`grantpt(master)` и `unlockpt(master)`) и открываю его. Также копирую размер окна. 

В дочерний процесс передаю slave конец терминала. Открываю новую сессию (`setsid()`), назначаю slave конец управляющим терминалом в сессии (`::ioctl(slave_fd, TIOCSCTTY, 0)`) и перенаправляю через `dup2` потоки `STDIN_FILENO`, `STDOUT_FILENO`, `STDERR_FILENO` в slave конец терминала.

В родительском процессе сохраняю текущие настройки терминала и перевожу его в сырой режим (функция `terminal::enter_raw`). Для восстановления терминала в старые настройки написана RAII-обертка `Restore`, которая принимает старые настройки и в деструкторе вызвает `tcsetattr()`.

Далее, родительский процесс вызывает `terminal::relay`, двунаправленная передача данных Master -- Slave. Реализовано на epoll.
