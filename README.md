# Сборка и запуск
Для сборки необходим cmake и компилятор для c++ с поддержкой c++23
```
mkdir build && cd build
cmake .. 
cmake --build .
```

Для тестирования работоспособности необходим образ ФС. Тестировалось на linux alpine
```
mkdir -p /tmp/alpine
cd /tmp/alpine
wget https://dl-cdn.alpinelinux.org/alpine/v3.19/releases/x86_64/alpine-minirootfs-3.19.0-x86_64.tar.gz
tar -xzf alpine-minirootfs-3.19.0-x86_64.tar.gz
rm alpine-minirootfs-3.19.0-x86_64.tar.gz
```

Пример запуска контейнера
```
./runtime --rootfs /tmp/alpine /bin/sh
```

# Реализация
Создание дочернего процесса из лабораторной 3.

Master и Slave концы терминала открываются в конструкторе PtyChannel. 
С помощью `posix_openpt` получаю master handle, делаю его не управляющим (O_NOCTTY). Выдаю права, разблакирую slave конец (`grantpt(master)` и `unlockpt(master)`) и открываю его. Также копирую размер окна. 

В дочерний процесс передаю slave конец терминала. Открываю новую сессию (`setsid()`), назначаю slave конец управляющим терминалом в сессии (`::ioctl(slave_fd, TIOCSCTTY, 0)`) и перенаправляю через `dup2` потоки `STDIN_FILENO`, `STDOUT_FILENO`, `STDERR_FILENO` в slave конец терминала.

В родительском процессе сохраняю текущие настройки терминала и перевожу его в сырой режим (функция `terminal::enter_raw`). Для восстановления терминала в старые настройки написана RAII-обертка `Restore`, которая принимает старые настройки и в деструкторе вызвает `tcsetattr()`.

Далее, родительский процесс вызывает `terminal::relay`, двунаправленная передача данных Master -- Slave. Реализовано на epoll.

# Вопросы
## роль управляющих байт (escape-последовательностей)
Управляющие байты и escape-последовательности — это механизм, с помощью которого программа управляет поведением терминала: перемещает курсор, меняет цвета, очищает экран, переключает наборы символов и т.д. В Linux консольный драйвер реализует большое подмножество управляющих последовательностей VT102 и ECMA-48 / ISO/IEC 6429 / ANSI X3.64, а также собственные private-mode последовательности для изменения палитры цветов и отображения символов [[man](https://man7.org/linux/man-pages/man4/console_codes.4.html)]. PTY сам по себе не интерпретирует escape-последовательности, он лишь передаёт байты между программой и эмулятором терминала. Интерпретацию выполняет эмулятор терминала (xterm, GNOME Terminal и др.), следующий тем же стандартам.
## почему канонический режим ввода хоста ломает работу интерактивных консольных приложений внутри контейнера
В каноническом режиме:
- Ввод данных осуществляется построчно. Строка ввода — строка до одного из разделителей (NL, EOL, EOL2; или EOF в начале строки). 
- Разрешено редактирование строки (стирание, удаление; а также, если установлен флаг IEXTEN, — WERASE, REPRINT, LNEXT). read() возвращает не более одной строки ввода; если read() запросил меньше байтов, чем доступно в текущей строке ввода, возвращается только столько байтов, сколько запрошено, а оставшиеся символы будут доступны для чтения при последующих вызовах read().
- Максимальная длина строки составляет 4096 символов (включая завершающий символ новой строки); строки длиннее 4096 символов обрезаются. После 4095 символов обработка входных данных (например, обработка ISIG и ECHO*) продолжается, но любые входные данные сверх этого не обрабатываются — до 4095 символов включительно (не включая завершающий символ новой строки), при этом символ новой строки отбрасывается. Это гарантирует, что терминал всегда сможет добавить дополнительную информацию, пока не станет доступна хотя бы одна строка.

В неканоническом режиме ввод доступен немедленно (пользователю не нужно вводить символ-разделитель строки), построчная обработка и редактирование строки отключены. Буфер чтения принимает только 4095 символов; этого достаточно, чтобы обеспечить место для символа новой строки на случай переключения режима ввода в канонический.

Интерактивным приложениям — редакторам (vim, nano), программам на ncurses (htop, mc) — нужен посимвольный ввод в реальном времени: каждое нажатие клавиши должно быть доставлено программе немедленно, чтобы она могла отреагировать на него (переместить курсор, перерисовать экран, обработать горячую клавишу). Канонический режим этого не позволяет.
